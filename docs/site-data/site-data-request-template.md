# Site Data Request Template (Sprint 53)

This document is the **customer / operator-facing** template AquaOptima
uses to request a minimum viable pump-system export. Sprint 53 reads
only an exported / uploaded dataset; AquaOptima does not connect to
your historian, SCADA, OPC UA, PLC, PAC, or controller. The site PLC
retains direct VFD / pump / actuator authority throughout.

Safety boundary, restated:

- no live OT binding
- no PLC/PAC/SCADA write
- no command emission
- no setpoint output
- no control-loop closure

## What we are asking for

We need a pump-system export covering one or more pumps over a
representative operating window. The export lets us test our
differentiable Pressurised Hydraulic Model (dPHM), differentiable
parameter learning (dPL), and the dPHM-PINN model without AMAX and
without live OT integration.

## Minimum viable dataset

Please export the following channels for each pump:

1. **Timestamp.** ISO-8601 timestamps with a clearly declared
   timezone (UTC is best; otherwise the IANA name of the local
   timezone, e.g. `Europe/London`).
2. **Pump state.** Either an on / off / running enum
   (`pump_status`) or a boolean run flag (`pump_running`).
3. **At least one pressure channel.** Discharge pressure
   (`discharge_pressure`) is preferred; suction pressure
   (`suction_pressure`) is acceptable. Please declare the engineering
   unit (bar, kPa, psi, m, or mWC).

Strongly recommended additional channels:

- **Pump speed proxy.** One of `pump_speed_rpm`, `vfd_frequency_hz`,
  or `speed_percent`. Required if the pump is VFD-driven.
- **Hydraulic output.** `flow_rate` (in m³/h, L/s, gpm, or m³/s) is
  ideal. If no flow meter exists, a `tank_level` trend (m, ft, or %)
  is an acceptable substitute.
- **Electrical telemetry.** `pump_power_kw`, `current_amp`,
  `energy_kwh`.
- **Status channels.** `valve_status`, `alarm_state`, `trip_state`,
  `operating_mode`, `manual_auto_mode`.
- **Weather / demand proxy.** Ambient temperature, rainfall, or a
  downstream demand signal that helps explain hydraulic behaviour.

## How to send the data

Acceptable export formats:

- CSV (UTF-8, newline-delimited, one column per tag)
- Parquet (one column per tag)
- Historian point-history export (OSIsoft PI / AVEVA / IP.21 / OFS /
  etc.)
- SCADA archive dump (Wonderware, iFIX, Ignition, Citect, WinCC)

We additionally ask for a **tag-map spreadsheet** mapping your tag
names to the canonical AquaOptima roles. A template is generated by
`default_site_tag_map_template()` in the SDK.

Please do **not** include passwords, tokens, API keys, license keys,
historian connection strings, or any other credential in the export.

## What we will return

We will:

1. Run the SDK readiness assessment
   (`assess_site_data_readiness`) on the export.
2. Send back a readiness verdict — `good`, `usable`, `poor`, or
   `blocked` — with the list of missing required fields, optional
   fields present, blocking gaps, and warnings.
3. If the verdict is `good` or `usable`, run dPHM / dPL / dPHM-PINN
   replay tests on the export and report model-quality metrics.
4. If the verdict is `poor` or `blocked`, list the specific channels
   or declarations we need before re-evaluating.

## Sampling cadence

Target sampling interval: **1 second to 60 seconds**. Faster sampling
is welcome; slower sampling may downgrade the readiness verdict.

## Example column layout (CSV)

```
timestamp,pump_status,pump_speed_rpm,suction_pressure,discharge_pressure,flow_rate,pump_power_kw
2026-01-01T00:00:00Z,running,1450,1.20,4.30,18.5,11.2
2026-01-01T00:00:01Z,running,1452,1.21,4.31,18.6,11.3
```

The pipeline accepts any column ordering; the tag-map spreadsheet is
the authority for column → canonical role mapping. Units must be
declared either in the column header or in the tag-map spreadsheet.

## Questions

If a column you have does not appear in the canonical role list, send
it along anyway and note its meaning. The SDK will surface unknown
tokens as warnings, not blocking gaps.
