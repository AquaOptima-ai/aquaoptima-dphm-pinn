## 100-node topology summary

`make_grid_network(rows=10, cols=10, seed=0)` returns the Sprint 10
target fixture:

| Property              | Value |
|-----------------------|-------|
| Nodes                 | 100   |
| Edges                 | 180   |
| Pipe edges            | 180   |
| Pump edges            | 0     |
| Fixed-head nodes      | 1 (corner reservoir at 100.0 m head) |
| Free nodes            | 99    |
| Newton iters to 1e-7  | 6     |

The pipe-only mesh keeps the solver in a basin where the analytic
Jacobian converges deterministically across seeds 0, 1, 7, 42 (manually
verified). The reservoir absorbs the per-step demand drift so
`sum(demands) == 0` holds at every timestep.

## Telemetry generation method

Sprint 10 telemetry is generated by
`generate_physics_consistent_telemetry(..., jacobian_mode="analytic")`:

1. A deterministic per-step demand pattern is built (cosine daily
   modulation plus seeded noise around the network's nominal demands).
2. Drift is redistributed onto the supply node so mass balance holds.
3. The Sprint 9 analytic-Jacobian Newton solver computes physics-
   consistent heads and flows at each step.

`jacobian_mode` defaults to `"autograd"` for backward compatibility;
the Sprint 10 tests opt in to `"analytic"` explicitly. A parity test
(`test_telemetry_analytic_and_autograd_match_on_small_grid`) verifies
both modes produce identical telemetry within solver tolerance on a
5x5 fixture.

## Residual evidence

`tests/dataio/test_100_node_physics_telemetry.py`:

* `test_100_node_telemetry_residual_is_small_at_every_step` — for a

  all timesteps is bounded below `1e-3`. Measured max residual on the

* `test_100_node_batched_residual_matches_unbatched_energy_block` —
  per-row energy block matches the unbatched call to `1e-9` atol
  across all 8 batch rows.
* `tests/training/test_sprint10_100_node_gate.py::test_sprint10_batched_residual_on_100_node_grid`
  — at the initial guess (uniform heads / flows across the batch),
  every row of the batched residual is **bit-equivalent** to the
  unbatched residual (atol `1e-12`).

## Science gate result

`test_sprint10_100_node_science_gate_sensor_plus_physics_wins`
exercises the same two-arm ablation Sprint 5-8 used (sensor-only
vs. sensor+physics) on the 10x10 / 100-node grid with `B=8`,
60 iterations, hidden_dim=16, lr=1e-3, and a 20-step linear-ramp
lambda warmup ending at `1e-4`:

| Arm                  | final_physics | final_data | Wall time |
|----------------------|--------------:|-----------:|----------:|
| sensor_only          |     6.881e+09 |  1.625e+03 |    ~1.7 s |
| sensor_plus_physics  |     5.129e+07 |  2.082e+03 |    ~1.7 s |

Ratio `sp / so` on the physics residual: **7.45e-03** (the gate bar
is `< 0.1`). Verified across additional seeds (1, 7, 42) — ratios
range from `4.66e-06` to `7.45e-03`, comfortably below the gate.

A smoke gate (`test_sprint10_100_node_smoke_gate`) runs 20 iterations
of the sensor+physics arm and asserts every metric stays finite. This
exists so a Sprint 11 regression on the larger fixture is caught
quickly with a clear error.

Max-residual numbers are bounded by the float32 cast at the
generator -> downstream boundary; the underlying float64 solve
converges to `1e-7`. The 10x10 fixture used by the automated science
gate fits comfortably (~1.5 s telemetry + ~3.5 s training) inside
the CI budget.

Telemetry-generation runtime on the 10x10 grid is **dominated by the
linear solve and incidence-matrix construction** — both dense O(N^3).
Sparse / Krylov solvers are the obvious next lever; this is the
Sprint 11 recommendation below.

## Compatibility notes

* `generate_physics_consistent_telemetry(...)` retains its previous
  default behavior: the new `jacobian_mode` keyword defaults to
  `"autograd"`. Sprint 1-9 callers see no behavior change.
* `Network`, `make_grid_network`, `load_network_from_json`,
  `newton_solve`, `assemble_residuals`, and
  `assemble_residuals_batched` are bit-for-bit identical to Sprint 9.
* The grid fixture's incidence cache (Sprint 9) is re-built once per
  `replace(network, demands=...)` call inside the per-step telemetry
  loop; this is a known minor perf nick, not a correctness issue.
* No SCADA / PLC / PAC / historian adapter, write path, dPL parameter
  learner, ONNX / TensorRT export, or real EPANET dependency was
  introduced.

## Limitations

* The science gate still uses the synthetic grid fixture, not a real
  EPANET / WNTR network. Importing real reference networks (e.g.
  Net1, Net3, KY1) is deferred to Sprint 11 and is the recommended
  next sprint focus.
* The Newton solver remains dense. On 12x12 (144 nodes) the per-step
  solve is already 70 ms; scaling to thousands of nodes will require
  sparse / Krylov methods (also deferred).
* `assemble_jacobian_analytic` still uses a Python loop to fill the
  energy / free-head block (Sprint 9 limitation, not gating).
* The float32 cast at the generator -> downstream boundary inflates
  the observed residual norm to ~5e-5 at the 10x10 grid; the
  underlying float64 solver converges to `1e-7`. The downstream
  pipeline operates in float32 by convention, so this is intentional.

## Sprint 11 recommendation

Pick **EPANET/WNTR topology import** next.

Rationale:

* The Sprint 8 JSON loader + Sprint 10 100-node grid prove the
  topology surface scales — but every fixture in CI is still
  synthetic. A real reference network is the next thing that buys
  external credibility for the science gate.
* WNTR is pip-installable and reads `.inp` directly. The integration
  fits in `aquaoptima.dphm.network_io` next to `load_network_from_json`,
  and can be **optional**: tests skip if `wntr` is not installed,
  matching the Sprint 10 prompt's "no real EPANET execution
  dependency unless it is optional and tests do not require it"
  scope.
* Sparse / Krylov solvers (the alternative branch) buy 10x-100x
  speedup on 1000+ node networks — but with no real reference
  network to validate against, the work is hard to verify. Do
  EPANET/WNTR import first, then sparse solvers in Sprint 12.
* Sensor placement / observability is also attractive but better
  framed once a real network with known sensor topology exists.

If EPANET/WNTR import slips, the fallback is sparse/Krylov on the
existing synthetic grid fixtures.
